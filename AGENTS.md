# Notes for coding agents

Cavern is a small Metroidvania (one connected cave world in five areas that
opens up as the hero finds abilities) built on GameLib
(https://github.com/alonohana627/GameLib, locally `C:\Users\user\GameLib`; a
separate repository). It is the fourth platformer of GameLib's run
(`GameLib/GAME_SUGGESTIONS/08-cavern.md` is its spec).

## Ground rules

- Consume GameLib only through its CMake targets (`GameLib::core`,
  `GameLib::app`, ...) and public headers (`<gamelib/...>`). Never copy GameLib
  sources into this repository or include its `src/` files. Use what GameLib
  offers (its `FEATURES.md` at the pinned commit) instead of rewriting it.
- GameLib is pinned by full commit hash in `CMakeLists.txt` (`GIT_TAG`,
  `GIT_SHALLOW FALSE`). Bump it only together with a row in
  `docs/GAMELIB_REVISION.md`. GameLib keeps no backwards compatibility.
- GameLib is changed only to fix a bug that blocks the game (GameLib commit
  with a headless test first, then a re-pin). Generic code the game had to
  write itself is kept separable and reported as a P0 candidate for GameLib's
  `FEATURE_SUGGESTIONS.md`; this repository has no feature-suggestions file.
- Snake, Tetris, Pong, Breakout, Asteroids, Invaders, Minesweeper, Leap,
  Bounder and Blaster are read-only references.
- Every visual is generated by shaders (GameLib's built-in shapes or this
  game's `shaders/`). No image files. Every sound and the music are
  synthesized with GameLib's synth.
- The wanderer, the creatures and the guardians are original characters;
  keep them that way (no trademarked looks or names).
- `src/game` (the world, rules, the session, the demo recording) links only
  `GameLib::core` and `GameLib::ai`: no window, GPU, audio or clock;
  deterministic for the per-tick input. Presentation, menus, sounds and
  saves live in `src/app`.
- **Games have no tests**: no unit tests, no test executables, no
  `GameLib::testing`. The only CTest entry is the template's smoke run
  (`--hidden --require-validation --frames 120`), which enforces zero Vulkan
  validation messages on the title screen.
- Zero compiler warnings, zero shader warnings (glslc `-Werror`), zero
  validation messages.
- Small Conventional Commits (`feat(game):`, `feat(app):`, `fix:`, `build:`,
  `docs:`) after each step that builds and runs. Stage files explicitly;
  never commit build output. Never rewrite history. Push `main` to origin
  after each commit.
- `FEATURES.md` lists what the game does today, verified by running it;
  update it in the same commit as each feature; never list planned work.
- Run the game and look at it after every visual change (GameLib's
  self-test switches plus the `win32-game-window-automation` skill for
  screenshots). Do not drive F11 in automated runs: fullscreen takes over the
  monitor.

## Skill suggestions

Keep `SKILL_SUGGESTIONS.md` up to date: at the start of a session list
`~/.claude/skills/` and move newly installed skills to "Already installed";
add or sharpen an entry (kebab-case name, one paragraph, a "Why") whenever a
task would have gone better with a missing skill. Mention changes in one line.

## Layout

```text
CMakeLists.txt, CMakePresets.json   project, GameLib pin, presets, the smoke run
src/game/   rules -> GameLib::core (+ GameLib::ai)
            rules.*          numbers, the hero's tuning per ability set, Input and its text form
            world.*          RoomDef, the World built from the room text (doors, cracked tiles,
                             items, stations, enemies, guardians, passages for the map)
            world_*.cpp      the rooms of each area; world_text.cpp the signs and tablets
            session.*        one run: rooms and scrolls (core::RoomScroll), doors, breakables,
                             items, stations, saves' Progress, escape, events
            hero.cpp         the controller with abilities, swimming, slash, shot, pound, thorns
            enemies.cpp      the fifteen creatures
            bosses.cpp       the four guardians and the molten heart (StateMachine, PhaseByHealth)
            demo.*           the recorded demo through the first rooms
src/app/    presentation -> GameLib::app, ui, fx, ai, storage
            cavern_game.*    the Game: title + demo, slots, play, map, signs, death, ending
            screens.cpp      drawing the HUD, minimap, map screen, slots, ability scene, ending
            view.*           the world: camera (Camera2D per room), backdrop, tiles, props,
                             creatures, guardians, shots, lights
            effects.*        shards, sparks, dust, rings, ambient motes, shake and flash
            actions.*        the ActionMap (rebindable keys and gamepad)
            saves.*          three save slots (storage::SaveSlots) holding a Progress
            profile.*        cavern.ini (settings, bests, key bindings, last slot)
            sounds.*         synthesized effects and ten tunes
            palette.*        a core::Palette per area
src/main.cpp                AppConfig and runMain
shaders/    tile, backdrop, hero, enemy, boss, item, shot
docs/GAMELIB_REVISION.md    the GameLib commit each change was validated with
```

## World text

The world is a grid of map cells; one cell is one screen of 32 x 18 tiles
(16 world units each). A room (`RoomDef`) has a corner cell, a size in cells
and exactly `size.y * 18` rows of `size.x * 32` characters (`world.hpp` lists
every tile and marker). Rooms side by side join where both have an opening
on the shared edge: the loader refuses an opening that faces rock or
nothing (only the ruins may open to the sky). Doors written on both sides
of an edge are one door. Numbers from the controller: a held jump rises
3.4 tiles (a 3-tile ledge is the most), a running jump clears 4 tiles; the
dash crosses 6-tile gaps, the double jump reaches 5-tile ledges; glassy
crystal ('*') cannot be clung to, so double-jump ledges are glass.

## Developer aids

- `CAVERN_START_LEVEL=N`: a new or loaded slot starts in room N (the order
  of the world files) with every ability and key.
- `CAVERN_REPLAY=<file>`: a recording (`core::InputRecording` text, the
  seven-character inputs of `rules.hpp`) drives the run. These are GameLib's
  `app::readDevStart("CAVERN")`.
- `CAVERN_SCENE=ability0`..`ability3` (an "ability get" scene), `map` (every
  room revealed), `escape` (the heart beaten, the escape running; best with
  `CAVERN_START_LEVEL=55`) or `ending`: a look at those scenes from PLAY.
- `--demo`: the recorded demo plays full screen. `--keep-running`: the game
  keeps running without focus, for screenshot scripts.
- `CAVERN_DATA_DIR`: where `cavern.ini` and the `saves` folder live.

## Commands

```powershell
cmake --preset debug           # configure (fetches GameLib from GitHub at the pinned commit)
cmake --build --preset debug
ctest --preset debug           # the smoke run (validation layer required)
build/debug/bin/cavern.exe     # --demo: the demo plays full screen
```
